## 1. الخلاصة التنفيذية

| السؤال | الجواب المختصر |
|---|---|
| هل الوكيل «حقيقي مسار واحد»؟ | **لا بعد.** الحلقة الأساسية حقيقية (LLM يختار الأدوات)، لكن التداول مركّب حولها: راوتر كلمات مفتاحية عربي/إنجليزي، مسار سريع يتجاوز النموذج، أنبوبتان متوازيتان، 3 متغيرات بيئة تبدّل السلوك، وشخصيتان (`nanobot` و`Lonora`). التفاصيل والأدلة في 01. |
| وكلاء يتناقشون مع بعض؟ | **موجود ويعمل بوكلاء LLM فرعيين حقيقيين** (`crew/debate.py`, `teams/runtime.py`). عيبان يُصلَحان: برومبتات الأدوار في YAML لا تُمرَّر، والاستدعاء أحياناً بالكلمات لا بقرار الوكيل. يظهر في Timeline كأحداث `subagent` (07). |
| القدرات 1–9؟ | **27 مكتملة / 21 جزئية / 2 مفقودة** من 50. الأضعف: القسم 4 (إدارة الصفقة: 0 مكتمل)، والمفقود: Fast Backtest (5.2) وتشفير المفاتيح (7.2). |
| البرومبتات؟ | مكررة في 3 أماكن، الدستور الفعلي غير محقون تلقائياً، عقد أدوات برمجي فوق منتج تداول. الحل: مُركِّب واحد بسبع طبقات (02). |
| الواجهة؟ | **قرار المالك: Open WebUI بنفس ملفات النظام.** fork `loorksy/nanoagent-webui` + Pipe Function تتحدث إلى بوابة الوكيل؛ مسارات Svelte للأقسام الأربعة الأخرى؛ `webui/` الحالية تُحذف بعد القطع. قيد الرخصة (تغيير العلامة ≤ 50 مستخدماً) موثّق في 04 §2. |
| الجوال؟ | **قرار المالك: React Native لـ iOS و Android** يستهلك نفس البوابة (REST/SSE/WS/Push). لا Push في أي من المشاريع الثلاثة → `nanobot/gateway/push/` (FCM v1 + APNs). |
| التنفيذ على MT5؟ | **قرار المالك: توصيات واقتراحات وتنفيذ حسب الصلاحيات.** ثلاثة مستويات `recommend / propose / execute` + منح مقيَّدة (لوت، جلسات، سقف خسارة، صلاحية زمنية) تُفرض قبل البوابات لا بدلاً منها (08). |
| الربط معقد؟ | 73 حقلاً رقمياً + 9 مفاتيح في صفحة واحدة. الحل: 3 ملفات مخاطرة + 7 منزلقات + 5 مفاتيح + بطاقة صلاحيات MT5؛ ≈50 حقلاً تُشتق آلياً أو تختفي إلى «متقدم» (04 §4). |

## 2. القرارات الثابتة (لا تُناقَش في التنفيذ)

1. **وكيل واحد، اسم واحد: NanoAgent.** لا `Lonora` كشخصية، لا `nanobot 🐈` في البرومبت، لا `LONORA_*` env vars. الويب و iOS و Android يتحدثون إلى **نفس الوكيل** عبر بوابة واحدة.
2. **لا توجيه بالكلمات قبل النموذج.** النموذج يقرأ ويقرر الأداة. الأدوات عقودها صريحة.
3. **نواة السلامة تبقى حتمية:** استدعاء القرار المبنيّ (JSON) هو الوحيد الذي يصدر BUY/SELL؛ البوابات تحجب ولا تقلب؛ HITL إلزامي للتنفيذ ما لم تسمح صلاحية مقيَّدة صريحة منحها إنسان (08)؛ خطة حية واحدة/محادثة؛ لا أسعار من الذاكرة؛ الوكيل لا يعدّل صلاحياته.
4. **لا عربية ولا نصوص ثابتة داخل منطق Python/Svelte/TSX.** كل النصوص في كتالوجات JSON (`nanobot/trading/locales/`، `GET /api/v2/labels`، `i18n` في الـ fork والتطبيق)؛ القوائم اللفظية (hawkish/dovish…) بيانات في `intel/lexicon/*.json`.
5. **الأرقام في `TradingRiskParameters`، القواعد في البرومبت.** لا حد رقمي داخل نص برومبت.
6. **XAUUSD فقط. TradingView فقط. `agent/loop.py` و`runner.py` يبقيان صغيرَين** (ملحقات عبر channels/tools/skills/gateway وفق `.agent/design.md`)؛ لا استيراد من `nanobot/gateway/` داخلهما.
7. **العملاء لا يعرفون البروتوكول الداخلي.** كل عميل (Open WebUI Pipe، RN، لوحات خارجية) يستهلك `/api/v2` والأحداث المعرَّفة في 07 فقط؛ النتائج منظّمة (`market / analysis / scenarios / risk / decision …`) لا نصاً حراً.
8. **الواجهة الجديدة ملفات جديدة** (fork منفصل + `nanobot/gateway/`)؛ `webui/` القديمة تُحذف عند القطع لا تُعدَّل.

## 5. معايير القبول العامة (Definition of Done للمشروع)

- `rg "[\u0600-\u06FF]" nanobot/ --glob '!**/locales/**' --glob '!**/fixtures/**'` → صفر؛ نفس الفحص على الملفات المضافة في الـ fork والتطبيق خارج `i18n/`.
- `rg -i "lonora" nanobot/` → صفر. `rg "LONORA_"` → صفر. لا `re.compile` لمطابقة نوايا المشغّل في `nanobot/trading/`.
- برومبت النظام يُولَّد من مُركِّب واحد؛ اختبار snapshot لكل قناة. 10+ سيناريوهات محادثة تثبت اختيار الأداة الصحيحة واللغة الصحيحة بدون راوتر.
- البوابة: انقطاع 30 ثانية بلا فقد أحداث؛ `cancel` يوقف أداة/subagent ≤ 2 ثانية؛ كل `structured` يطابق مخططه؛ لا استيراد من `gateway/` في `loop.py`/`runner.py`.
- الويب (Open WebUI fork) والجوال (iOS + Android) يعرضان نفس الجلسة ونفس الحالة ونفس Timeline؛ الأقسام الخمسة + 9 تبويبات إعدادات بالعربية (RTL) والإنجليزية؛ الربط ≤ 7 منزلقات و5 مفاتيح و3 عناصر تحكم + بطاقة الصلاحيات في الشاشة الأولى.
- الصلاحيات: `recommend` لا يلمس MetaAPI؛ `propose` = سلوك اليوم؛ `execute` ينفّذ داخل المنح فقط ويهبط تلقائياً خارجها مع إشعار وسجل؛ لا أداة للوكيل تغيّر الصلاحيات.
- الجوال: إقران QR < دقيقة؛ Push والتطبيق مغلق ≤ 5 ثوانٍ؛ تأكيد اقتراح بالبصمة يمر بـ HITL ويظهر في Log؛ Kill Switch يعمل.
- القسم 4 في المصفوفة: 6/6 مكتمل؛ 5.2 و 7.2 مكتملان؛ إجمالي ≥ 45/50 DONE.
- `pytest tests/trading tests/gateway -q` و`basedpyright` واختبارات الـ fork والتطبيق خضراء في CI.

| رخصة Open WebUI (تغيير العلامة > 50 مستخدماً) | نبقي شعار Open WebUI في About إن تجاوزنا الحد أو نشتري ترخيصاً؛ موثّق في 04 §2 |
| انجراف الـ fork عن upstream | تعديلاتنا في ملفات مضافة فقط + `FORK_NOTES.md` + rebase شهري على tag مستقر |
| قيود Pipe Function (لا UI مخصص داخل الشات) | النتائج المنظّمة HTML عبر `embeds`/Artifacts؛ ما يحتاج تفاعلاً غنياً يذهب إلى مسارات Svelte أو التطبيق |

| Push غير موثوق | تسليم عبر WS إذا الجهاز متصل، Push احتياط؛ إعادة تشغيل SSE بـ `Last-Event-ID`؛ inbox في التطبيق كمصدر حقيقة |
| الواجهة الجديدة تكسر التدفقات الحالية أثناء البناء | تشغيل مزدوج `/` و`/legacy` حتى القطع؛ البوابة إضافة لا تعديل |
| توسّع نطاق الترحيل من AiChart/foxagent | قائمة مرفوض صريحة (06 §3) |
